# OverQubit 开发规划 — 超导量子比特原理直观模拟

- 日期：2026-09-22
- 依据：《01_调研报告_超导量子比特模拟可视化.md》
- 选型结论：**混合（薄自研壳 + 复用求解器）**
- 本文性质：**供讨论的方案对比**，不是已拍板的实施令。架构/形态需与你共同定夺后才开工。

---

## 1. 产品定位

**一句话**：一个「打开就能拖参数、立刻看懂超导比特原理」的交互小软件；求解交给 scqubits / QuTiP，自己只做「直观展示」。

**要服务的三类需求**

| 优先级 | 需求 | 在产品中的样子 |
|---|---|---|
| P0 | ① 教学式交互演示 | 势阱/能级/Bloch 联动视图，拖 EJ、EC、ng、drive 参数即时重绘 |
| P0 | ② 动力学过程可视化 | Rabi / Ramsey / T1 / T2 / 脉冲驱动的时域动画，与能级/Bloch 联动 |
| P1 | ③ 参数扫描与静态图 | 能级-磁通、色散、频谱扫参图；可导出 PNG/CSV，或一键跳到 scqubits notebook |

**明确不做（MVP 外）**

- 自研数值求解器（ODE、对角化、主方程）
- 芯片版图 / GDS / HFSS / EPR 提取（Quantum Metal、pyEPR 链路）
- 多比特纠错、大规模线路编译
- 移动端原生 App

## 2. 架构与形态：两套备选方案

### 方案 A — 本地 Web 应用（推荐）

```
┌─────────────────────────────────────────────────┐
│  UI 壳层（浏览器）                                 │
│  参数面板 │ 势阱图 │ 能级图 │ Bloch │ 时域波形 │ 谱图  │
└───────────────────────┬─────────────────────────┘
                        │ JSON / WebSocket
┌───────────────────────┴─────────────────────────┐
│  应用服务（Python，如 FastAPI）                    │
│  会话状态 · 参数校验 · 结果缓存 · 预设/实验脚本        │
└───────────────────────┬─────────────────────────┘
                        │ Python API（进程内）
┌───────────────────────┴─────────────────────────┐
│  求解层（不自研）                                   │
│  scqubits：能谱 / 矩阵元 / 弛豫                     │
│  QuTiP：含时动力学 / 主方程 / Bloch                  │
│  （可选）qutip-qip：脉冲级 qubit-腔                  │
└─────────────────────────────────────────────────┘
```

- **形态**：`uvicorn` 起本地服务，浏览器访问；控件用滑块/下拉，绘图用 Plotly 或 ECharts（可交互缩放）。
- **技术栈建议**：Python 3.11+、FastAPI、scqubits、qutip、numpy/scipy；前端 Vue 或 React + Plotly；若想更轻，可用 **Panel / Bokeh** 或 **Streamlit** 写第一版（见下文「形态变体」）。
- **优点**：交互反馈好、易做出「拖参数即时重绘」、跨平台（Windows 也方便）、后续可部署到局域网分享给同学/同事。
- **缺点**：比 notebook 多一层服务与前后端约定；打包成单文件 exe 需额外工作（PyInstaller + 前端静态资源）。
- **适合**：你的原话「直观展示模拟结果的小软件」——产品感优先。

### 方案 B — Jupyter 面板（notebook 形态）

```
Jupyter Notebook
  ├─ ipywidgets 滑块（EJ/EC/ng/驱动幅度/时间）
  ├─ matplotlib / ipywidgets.Output 画布
  └─ 直接 import scqubits / qutip   ← 无服务层
```

- **形态**：一组主题化 notebook（实验 01 势阱与非谐性、实验 02 能级扇形图、实验 03 Rabi、实验 04 Ramsey/T2…），每个 notebook 顶部有控件，改参数重跑单元格或用 `interactive` 自动重绘。
- **技术栈**：JupyterLab、ipywidgets、matplotlib 或 bqplot、scqubits、qutip。
- **优点**：零前端工程、和科研工作流无缝、③ 静态图最强、教学可配讲义文字。
- **缺点**：交互流畅度与「软件感」弱于方案 A；改参数常要重跑 cell；给非 Python 用户使用门槛高。
- **适合**：学习者自己也写代码、要和论文/notebook 工作流混用。

### 对比表

| 维度 | A 本地 Web | B Jupyter 面板 |
|---|---|---|
| ① 教学交互体验 | **优**（实时联动、动画） | 中（cell 重跑、联动弱） |
| ② 动力学可视化 | **优**（时间轴动画） | 中（静态图 + 手动扫时间） |
| ③ 静态扫参图 | 优（可做） | **优**（scqubits 原生） |
| 开发成本 | 中（前后端） | **低** |
| 分享给他人 | **易**（发个 URL / exe） | 中（要装 Python 环境） |
| 与科研脚本互通 | 中（导出数据） | **优** |
| 打包成「小软件」 | 中（可 PyInstaller） | 低（本质是文档） |
| 可维护性 | 模块边界清晰 | notebook 易散乱 |

### 形态变体（可在 A/B 上叠加）

1. **A-lite**：用 **Streamlit / Panel** 单文件起 UI，跳过自写前端 —— 最快拿到「拖参数看图」的体验，后期若需要更强交互再换 Vue/Plotly。
2. **混合交付**：内核 + 同一套求解封装，同时出「Web 壳」和「教学 notebook 包」——notebook 负责 ③ 与深度推导，Web 负责 ①② 演示。

### 推荐倾向（待你拍板）

**倾向 A-lite 起步 → 方案 A**。理由：你的核心诉求是「直观展示」，Streamlit/Panel 能在很短路径上验证交互是否真的帮助理解；若验证有效，再把壳层升级为正式 Web 应用。方案 B 作为**并行副产品**保留（同一求解封装生成教学 notebook），成本低、覆盖 ③。

## 3. 模块划分（两套方案共用内核）

| 模块 | 职责 | 复用 / 自研 |
|---|---|---|
| `solvers` | 能谱、矩阵元、跃迁、弛豫率、含时演化 | **复用** scqubits / QuTiP（qutip-qip 可选），只做薄封装与单位统一 |
| `models` | 预置物理模型：transmon、fluxonium、transmon+谐振腔、两比特耦合 | 自研「模型定义」（参数字典 + 求解调用），物理仍是库的 |
| `experiments` | 实验脚本：能级扇形图、Rabi、Ramsey、T1、T2、连续波谱 | 自研编排逻辑（调用 solvers，返回统一 Result） |
| `viz` | 势阱、能级图、Bloch、脉冲波形、时域布居、谱热图 | 自研（Plotly/matplotlib），这是产品的价值所在 |
| `presets` | 教学预设：「典型 transmon」「过浅/过深势阱」「大非谐 vs 小非谐」 | 自研 |
| `shell` | UI（Streamlit/Panel 或 FastAPI+前端） | 自研薄层 |

**接口约定（关键）**：`experiments.run(exp_id, params) -> Result`，`Result` 含 `meta`（单位、模型名）、`series`（可绘图数据）、`bloch_path`/`states`（可选）。UI 只认 `Result`，不直接摸 scqubits 对象。这样 A/B 两套壳可互换。

## 4. MVP 功能清单

**MVP-0（内部验证，约 1 个周末）**

- [ ] transmon 模型：给定 EJ/EC，输出能级 E0..E3 与非谐性 α
- [ ] 一张势阱图：−EJ cos(φ) + ½ EC n² 相关的直观势 + 能级横线
- [ ] 一张能级-EJ/EC 或能级-ng 扇形图（scqubits）
- [ ] 命令行或 notebook 跑通，确认数值与文献典型值同量级

**MVP-1（可演示的教学原型 = A-lite）**

- [ ] 滑块：EJ/EC、ng、驱动幅度、驱动失谐
- [ ] 联动视图：势阱 + 能级（含 α 标注）
- [ ] 单位标注（GHz / MHz）与「典型参数」一键预设
- [ ] Rabi 演示：拖驱动幅度/失谐，布居 |0⟩/|1⟩ 随时间变化（动画或轨迹）
- [ ] Bloch 球显示当前/演化态

**MVP-2（补全 ②③）**

- [ ] Ramsey / T1 / T2 实验脚本 + 时域图
- [ ] 连续波谱或色散移 χ 的扫参热图/曲线
- [ ] 导出 PNG / CSV；或一键打开对应教学 notebook
- [ ] 至少 2 个教学预设（「为什么用 transmon 而不是电荷 qubit」「非谐性与门速度」）

**明确延后**：fluxonium、多比特纠缠动力学、噪声功率谱拟合、脉冲优化（DRAG 等）。

## 5. 里程碑

| 阶段 | 产出 | 验收 |
|---|---|---|
| M1 求解封装 | `solvers` + `models` 最小集 | 脚本输出 transmon 能级/α，数值合理 |

| M4 打磨与分发 | UI 美化、预设、文档 | 可发给别人打开即用（或 notebook 包） |

## 6. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| scqubits 在 Windows/conda 下安装摩擦 | 求解层跑不起来 | 固定 conda-forge 路径；M1 先做冒烟脚本 |
| 交互频率过高导致求解卡顿 | 「即时反馈」变成「转圈」 | 低维截断（Ncut 取小）+ 结果缓存 + 防抖（slider 停 150ms 再算） |
| 把壳做重、做成第二个 QuTiP | 失控 | 守住「不写求解器」红线；新物理优先用库 |
| 教学叙事不足，只是「能跑的图」 | 达不到「理解原理」 | MVP-2 起强制每个实验带 3–5 句「看什么/为什么」 |
| Qiskit Dynamics 已弃维护 | 若误依赖会背上包袱 | 主路径只用 scqubits + QuTiP |
